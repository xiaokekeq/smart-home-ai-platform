# 当前问题记录

## smartHouse 当前已发现的问题

### 1. 设备状态联动不完整
- `5G WI-FI` 的开关目前没有真正联动到其他设备的小 WiFi 图标。
- 现在很多设备只是各自显示自己的图标状态，更像演示数据，不像真实业务联动。
- 后续如果要改，建议把 `wifi` 作为一个全局网络状态，再决定哪些设备依赖它。

### 2. 空调总开关和详细控制原本是割裂的
- 左侧 `Air Conditioner` 小卡片和右侧空调大面板，原本没有真正联动。
- 现在已经接通了基本联动，但后面还可以继续优化表达方式。

### 3. 空调的开关和模式语义要分开
- `powerOn` 应该单独表示设备开关。
- `mode` 应该只表示运行模式，比如 `cool / heat / dry / auto`。
- 不建议把 `Power Off` 混进模式里。

### 4. 空调关机后的禁用态需要统一
- 关机后不应该还能继续修改模式、风速、定时。
- 禁用时不仅要禁止交互，也要让按钮、圆环、文字一起变灰。
- 这一点现在已经做了第一版处理。

### 5. 空调图标语义可以更准确
- 当前空调设备如果一直用雪花图标，更像“制冷模式”。
- 如果想表达“空调设备本身”，后面可以考虑换成更贴近设备语义的图标，比如 `mdi-air-conditioner`。

### 6. 响应式适配一般
- 拖拽 Chrome 窗口缩小时，页面不是优雅缩放，而是容易出现组件挤在一起的情况。
- 这说明页面内部有固定宽高、固定宽度和间距过大的问题。
- 这一项先记录，后面确定主页面后再集中处理。

### 7. 页面里有重复或表达不够清楚的设备控制
- `smartHouse` 里已经有空调控制区，如果后面还保留第二套类似控制，页面会显得重复。
- 后续可以考虑把某些区域替换成热水器、空气净化器、窗帘、扫地机器人等更合适的设备。

## 当前处理建议
- 现在先继续往后看，不急着集中修这些问题。
- 等主要页面和组件都看完后，再统一决定哪些问题要优先改。
- 真要改时，优先顺序建议是：
  1. 状态联动
  2. 设备语义和重复问题
  3. 响应式适配
