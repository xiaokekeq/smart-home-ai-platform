# 项目后端开发上下文说明

## 1. 当前项目目标
这是一个“车家互联平台”的前后端项目，前端已经基本完成了首页总览和智能家居页的主要结构，现在需要开始补 FastAPI 后端。

当前目标不是先做登录，而是：
1. 先把业务接口跑通
2. 先让前端从真实后端拿数据
3. 后面再补登录、鉴权、数据库、AI 接口

4. 首页当前业务逻辑
4.1 今日重点
前端当前是自己通过 computed 算的：

allFocusItems
visibleFocusItems
重点项目前由这些规则推导：

室内温度高且空调未开 -> 建议开启空调
窗帘未关且室外温度高 -> 建议关闭窗帘
车辆在线且车内空调未开 -> 建议开启车内空调
4.2 待处理告警
前端当前是自己通过 computed 算的：

allWarningItems
visibleWarningItems
告警项目前由这些规则推导：

摄像头离线
车门未完全关闭
车辆电量低且未充电
4.3 AI 建议
前端当前还是“规则模拟版”，还没有接真实 AI。
现在后端需要为以后 AI 接口预留结构，但第一步可以先不接大模型。

5. 后端开发优先级
第一阶段：不要做登录
暂时不要从 login / auth 开始。
原因：

当前前端最缺的是业务数据来源
不是用户系统
登录可以后补
第二阶段：先做业务接口
建议先做这几类接口：

5.1 Environment 相关

PATCH /api/environment/humidifier
5.2 Vehicle 相关

7. AI 后端策略
当前阶段：

不需要 LangChain
不需要 RAG
不需要向量数据库
原因：

现在 AI 只是首页一张建议卡
只需要结构化输出
不是文档问答，不需要检索增强
AI 第一版建议接口
可以预留一个：

POST /api/dashboard/ai-suggestion

输入示例：

{
  "home": {
    "temperature": {
      "indoor": 30,
      "outdoor": 31,
      "acOn": false,
      "targetAcTemp": 24
    },
    "light": {
      "on": true,
      "brightness": 80,
      "mode": "normal"
    },
    "curtain": {
      "openPercent": 100
    },
    "camera": {
      "on": true
    }
  },
  "vehicle": {
    "batteryPercent": 78,
    "remainingRangeKm": 420,
    "vehicleOnline": true,
    "charging": false,
    "cabinAc": {
      "on": false,
      "temp": 22
    },
    "allDoorsClosed": true
  },
  "warnings": [],
  "focus": []
}
输出建议：

{
  "title": "建议开启节能制冷",
  "desc": "当前室温 30°C，室外 31°C，可先将空调设为 24°C。",
  "actionText": "开启空调",
  "actionType": "openHomeAc"
}
actionType 第一版建议固定枚举
openHomeAc
closeCurtain
openCarAc
none

9. 当前开发原则
先对齐前端 store 结构
先让前端 overview 能从后端拿真数据
先做业务接口，不先做 login
AI 先做普通接口，不上 LangChain/RAG
先用内存 mock，后面再替换数据库
